# 手册导读

本页是对这套 Vite 手册（31 页）的导读：先给出一个总判断，再按「引擎定位 → 渲染 → 性能 → 参考」四条线说明手册讲了什么、结论是什么。读完整套手册之前，可以先读这一页。

## 一句话结论

整套手册只支撑一个判断：**UE5 用虚拟化与时间重建换取画质，Vite 则反过来，以原生分辨率与探针光照守住帧率。** 后续所有章节都是这个判断的展开、测量与工程实现。

## 一、引擎概览：这个分支为什么存在

Vite 是 **Unreal Engine 4.27** 的性能优先分支，构建于 NvRTX 与 Plus 分支之上。

为什么选 4.27 而不是 5.x：

- 4.27 原生支持 DXR 光追，渲染器结构简单、行为可预测；
- PhysX 在 4.27 仍然可用，且未像 UE5 那样被 Chaos 取代；
- BRDF 已足够现代，不需要为材质模型付出 UE5 的重构成本。

它的目标不是「UE5 的降级版」，而是换一套算法前提：

- 四档 PS5 级性能目标，且**每一档都包含光线追踪**——风格化 4K 120、性能与高端 4K 60、保真 4K 30、全光追 1440p 30；
- 相对 UE 5.7 的目标功能集，实际游戏帧率**最高可达 2.5 倍**，且以实测数据支撑；
- 官方对照实验：同一风格化场景、1440p 原生、RTX 4080 Super，Vite 为 **811 FPS**，UE 5.7 的 Lumen 为 **324 FPS**。

UE5 的成本来自哪里（成本分析页的核心）：虚拟阴影贴图的页表管理、Lumen 的多 pass 结构、Nanite 的 cluster 剔除与光栅化、TSR 的重投影与历史校验。这些属于算法前提决定的高固定成本，并非实现质量的问题——即使场景里什么都不建，渲染器本身也有底噪级的开销。

## 二、渲染：手册篇幅最长的部分

### 1. 两条全局光照路线

| 路线 | 做法 | 特点 |
|---|---|---|
| 动态 DDGI | 光线追踪辐照度探针体积，每帧更新 | 结构上无噪点，不需要降噪器；可比场景下帧率约为硬件 Lumen 的两倍 |
| 静态 DDGI | 沿用同一套探针表示，离线烘焙 | 烘焙近乎瞬时；反射保真度高于传统光照贴图，且能在**完全不支持光追的 GPU** 上运行 |

两条路线共用一套探针表示，因此可以在同一个项目中按场景切换，而不是二选一。

### 2. 光追四件套

- **RT 反射**：PS5 级 GPU 上可做到 4K 原生 60 帧；开启 DDGI 后，反射光线的二次弹射会采样探针辐照度，而不是返回黑色。
- **RT 阴影与环境光遮蔽**：与反射共用加速结构，避免重复构建 BVH；剔除由 `r.RayTracing.Culling` 系列控制。
- **半透明光追与焦散**：实验性质，默认关闭，按需开启。
- **RTXDI**：ReSTIR 直接光照，定位是 Lumen 中 MegaLights 的替代方案，噪点更少。

### 3. 光栅管线上的选择

- 环境光遮蔽保留 **HBAO+**；
- 抗锯齿用 **SMAA**，不启用 TAA，从根上避开重影与模糊；
- **DLSS / FSR / XeSS** 全部接入，质量模式可选，并提供 `VITE_DLSS_PATCH` 等编译期开关；
- **曲面细分**基于距离与位移，用来获得更平滑的表面和更干净的轮廓，而不引入 Nanite 的开销；
- 发丝渲染引入 **TressFX**（编译期开关 `VITE_TRESSFX`）；
- 材质侧使用更新后的 **Vite BRDF**，并配有线性色彩管理。

### 4. 明确的边界

- 默认构建**没有路径追踪**：它被 `VITE_RT_PSO_DEBLOAT` 精简掉了，重编（置 0）可启用；
- 没有 **DLSS Ray Reconstruction**；
- 半透明光追、焦散等属于实验特性，不建议作为量产默认值。

## 三、性能与优化：如何把上述特性装进帧预算

- **引擎默认值**：Vite 调整了一批 ini 默认项，其中约 39 项渲染特性默认关闭、1 项默认开启，目标是减少无用开销。
- **编译期开关**：十四个 `VITE_*` 宏，用编译期裁剪替代运行期判断；实测同场景从 235.56 FPS 提升到 264.44 FPS（+12.3%）。
- **着色器编译与 PSO**：说明卡顿的来源（首次遇到新的 PSO），以及预缓存与预热策略。
- **精简指南**：按项目实际用到的功能裁剪引擎，缩短编译时间与包体。
- **PS5 CPU 与 FPU**：SMT、浮点单元行为、编译器版本差异如何影响实测数字——提醒读者不要拿不同工具链的数据直接对比。
- **性能分析**：工具链、`stat` 命令族与 GPU 侧计时方法。
