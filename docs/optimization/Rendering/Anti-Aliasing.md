# 抗锯齿

!!! note "概要"
    Vite 在 None、FXAA、TemporalAA 与 MSAA 之外新增了第四种抗锯齿方法 **SMAA**，追求最高原始图像质量时推荐使用，竞技类作品尤其如此。Vite 同时改进了 **UE4 的 TAA**：稳定性、材质（尤其光泽材质）的色彩还原与纹理锐度都有提升。

Vite 新增了 **SMAA**（子像素形态抗锯齿，Subpixel Morphological Anti-Aliasing）作为第四种抗锯齿方法，与 None、FXAA、TemporalAA 和 MSAA 并列。SMAA 被推荐用于追求最高原始图像质量的游戏，尤其适用于竞技类游戏。Vite 也改进了 **UE4 的 TAA**：稳定性更好，材质（尤其是光泽材质）的色彩还原更准确，纹理也更锐利。

抗锯齿是 Vite 渲染理念最显著的体现。与 Epic 的虚幻引擎 5 不同，Vite 默认以原生分辨率渲染，并追求高帧率。因此，其抗锯齿方案优先考虑时间稳定性，同时保留原生 4K 输出的图像质量优势，更高的像素密度本身就能比较低的内部渲染分辨率减少锯齿。与 UE5 相比，当两个引擎在相同的输出分辨率但不同的内部渲染分辨率下进行评估时，Vite 有效地使用了超采样技术。

**注意：** Epic 的 UE 5.8 默认使用内部分辨率，其像素数仅为目标分辨率的四分之一——每个轴缩放 50%。这种行为出现在多种渲染路径中：即使禁用 TSR，引擎也可能“坚持”回退到其他非原生缩放方法，例如 TAAU 或基本空间放大。Vite 没有这种行为，它始终默认使用屏幕全原生分辨率。将 Vite 与 UE5 进行比较时，务必确认两个引擎都以相同的原生内部分辨率进行渲染。使用 `stat unit` 来确认当前分辨率和性能特征。


## 可用方法

“项目设置”>“引擎”>“渲染”>“默认设置”下的“抗锯齿方法”设置提供以下选项：

| 方法 | 枚举 | `r.DefaultFeature.AntiAliasing` | 说明                                                                                                |
|---|---|---|------------------------------------------------------------------------------------------------------|
| None | `AAM_None` | 0 | 不做抗锯齿，画面有锯齿。适合做对比，也适合调试抗锯齿伪影。                                       |
| FXAA | `AAM_FXAA` | 1 | 低成本的后处理滤镜，会把纹理细节和边缘一起模糊掉。Vite 的 FXAA 比原生实现质量更高、速度更快（3 月主要版本）。 |
| TemporalAA | `AAM_TemporalAA` | 2 | 相比 UE4 的 TAA，画质与稳定性都有改进。锯齿消除得干净，代价是牺牲一些锐度。 |
| MSAA | `AAM_MSAA` | 3 | 仅支持前向着色。采样数由 `r.MSAACount` 设置。 |
| **SMAA** | `AAM_SMAA` | **4** | Vite 推荐的方法。纯空间处理，不依赖历史缓冲区，提供四档质量。 |

## SMAA

亚像素形态抗锯齿 (SMAA) 分析图像的边缘模式，并以几何方式进行混合。它是一种空间技术：它只关注一帧图像，并解决该帧中的锯齿问题。

正是这一特性使其非常适合 Vite。时间技术会在帧之间累积样本，这会导致移动物体后方出现重影、快速镜头运动时出现拖影，以及 TAA 输出看起来像是在薄薄一层凡士林后面渲染的那种整体柔化效果。SMAA 没有历史缓冲区，因此不存在这些缺陷。它的不足之处在于无法重建亚像素细节——它无法恢复从未渲染过的信息——但当你本来就以原生 4K 分辨率渲染时，这一点就显得无关紧要了。

Vite 的第一版 SMAA 实现在虚幻引擎中实测比 CMAA2 快 32%，这也是 CMAA2 被认为多余的原因。其他形态学方案也评估过，没有一个能给出值得在 Vite 中实现它的客观理由。该实现前后经历了两代：

| 版本 | 实现 |
|---|---|
| 3 月主要版本至 7 月主要版本 | Vite 计算版 SMAA：三个计算通道，内联 SMAA 数学，质量由 `r.Vite.SMAA.Mode` 决定 |
| 8 月主要版本起 | 移植 Epic UE 5.7 的 SMAA 管线：边缘检测、仅对边缘像素做模板遮罩的混合权重计算，以及邻域混合；提供四档质量与可选的边缘检测方式 |

参考的 SMAA 算法本身与上游一致。Vite 从自己的实现里保留下来的，是 SMAA area 贴图与 search 贴图的异步加载，避免在渲染线程上加载纹理资源。


### 启用 SMAA

```ini
; Config/DefaultEngine.ini
[/Script/Engine.RendererSettings]
r.DefaultFeature.AntiAliasing=4
```

或者通过后期处理体积的**抗锯齿方法（Anti-Aliasing Method）**重写为每个摄像机单独设置，或者在运行时设置：

```
r.DefaultFeature.AntiAliasing 4
```

### 质量

| CVar | 默认值 | 值 |
|---|---|---|
| `r.SMAA.Quality` | `2` | `0` = 低，`1` = 中，`2` = 高，`3` = 超高 |
| `r.SMAA.EdgeMode` | `0` | `0` = 颜色边缘检测，`1` = 亮度边缘检测 |

`r.SMAA.Quality` 标记为 `ECVF_Scalability`，因此可以从可扩展性分组中驱动。默认为高，也是[性能目标](../EngineOverview/Performance-Targets.md)所假设的档位；低与中留给可扩展性更低的档位，那里用边缘质量的差异换取帧时间是划算的。颜色边缘检测能抓到亮度相近的不同颜色之间的边缘；亮度检测略便宜，在噪声较多的纹理中误判出的边缘更少。

!!! note
    7 月主要版本及更早的版本用的是 `r.Vite.SMAA.Mode`（`0` = 低，`1` = 高）和 `r.AntiAliasing.SMAA.Debug`。升级到 8 月或更新版本时请把这些名字从配置里改掉，旧名字会被静默忽略。


### SMAA 在管线中的运行位置

Vite 在**色调映射之前**应用 SMAA，这与在色调映射之后运行的 FXAA 不同。这是有意为之：在 HDR 线性空间中解析边缘可以避免色调映射器将部分解析的边缘像素放大到高对比度边界上的可见条纹，这是色调映射后 SMAA 实现的一个常见问题。

实际结果是，**色调映射后**混合位置中的后期处理材质看到的是已经抗锯齿的图像，并且 SMAA 可以与 HDR 输出正确合成。


### 调试

在非发布版本中：

| CVar | 值 |
|---|---|
| `r.SMAA.DebugVisualization` | `0` = 关闭，`1` = 边缘贴图，`2` = 混合权重，`3` = 场景颜色并高亮平滑后的边缘 |

当 SMAA 看起来什么也没做（通常是方法根本没选中）或者糊得过头（通常是源图像高频成分过多，往往来自激进锐化或降噪后处理）时，边缘可视化是最快的诊断手段。

## 抗锯齿无法解决的锯齿问题

有些锯齿并非光栅化引入，而是图像本身固有的，常规的抗锯齿方法无法解决：

- 光滑材质上高频法线贴图产生的**镜面反射锯齿**应通过正确的mip贴图生成和法线到粗糙度的转换来解决，而非使用抗锯齿。
- mip贴图缺失或生成错误导致的**纹理锯齿**。应在纹理导入设置中进行修复。
- 树叶上的**Alpha测试闪烁**。可以考虑使用抖动不透明度，或减少Alpha测试的表面积。

可以通过切换到`AAM_None`（无抗锯齿）并观察锯齿出现的位置来诊断这些问题。如果锯齿随表面移动而不是停留在轮廓边缘，则属于内容问题。
