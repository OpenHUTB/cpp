# 性能目标

!!! note "概要"
    四种 PS5 级参考配置，全部包含光线追踪：<b>4K120</b> 风格化、<b>4K60</b> 性能、<b>4K30</b> 保真，以及带完整光追效果套件的 <b>1440p30</b>。所有数字均为原生分辨率。


Vite 的性能目标不是空想的营销数字；它们就是引擎调校所对标的配置，也是各演示项目按之构建的配置。每一项都包含光线追踪，并且每一项都以原生分辨率给出，而不是超分后的内部分辨率。

[![Vite RT GI 与 RT Reflections](https://img.youtube.com/vi/2vfG3W-Gy5E/maxresdefault.jpg)](https://youtu.be/2vfG3W-Gy5E)

*光线追踪全局光照与光线追踪反射在 Vite 中运行。点击到 YouTube 观看。*

## 四个目标

| 目标 | 分辨率和帧率 | 功能集 | 适用于 | 展示于 |
|---|---|---|---|---|
| **风格化** | 4K, 120 FPS | RT DDGI | 多人竞技游戏 | 风格化演示 |
| **性能、高端** | 4K, 60 FPS | DDGI + RT 反射 + 曲面细分 | 追求保真度、但仍需要 60 帧的作品 | 虚幻竞技场 Vite 场景 |
| **保真、高端** | 4K, 30 FPS | 如上所述，按几何密度缩放 | 大型开放世界 | 演示开发中 |
| **保真、全 RT** | 1440p, 30 FPS | DDGI + RT 反射 + RTAO + RT 阴影 | 最高图像质量 | NVIDIA 演示 |

这四款配置的参考硬件均为 PlayStation 5 级别。在台式机上，CPU 侧重 FPU 的工作（PhysX 3.4、动画 SIMD）对应 **AMD 4700S**——相比 Series X 进一步精简的 Zen 2，只有一条 FMA 管线——GPU 则大致对应 RDNA2 RX 6700 / RTX 2080。4700S 的 GPU 已被熔断关闭。6700 在 RDNA2 编译器行为上已经足够接近，但它并不是 PS5 的 RDNA2。参见「PS5 CPU FPU」。

代码库中还包含一个用于参考图像的路径追踪器，默认不编译；参见[路径追踪](../Rendering/Path-Tracing.md)。实时路径追踪器正在作为 Vite ReSTIR 的一部分开发中。

## 比较的是什么

Epic 的 UE 5.7 和 5.8 的目标是在 PS5 上以 720p–1080p 的动态内部分辨率实现约 60 FPS，使用 Lumen、Nanite、VSM、TSR 和 Chaos。 Vite 的核心主张是：对照这套预期功能集，实际游戏帧率最高可提升 2.5 倍。

最清晰的单个演示：在 Vite 中运行的具有光线追踪全局光照、光线追踪反射和曲面细分的场景优于 UE 5.7 中没有光线追踪、没有 Lumen、没有 Nanite、没有曲面细分的“相同场景”。这在 RTX 4080 Super 的 4K 原生、RDNA2 RX 6700 的 4K 原生，以及 Steam Deck 硬件的原生分辨率下都成立。

## 测量参考点

这些是来自基准场景的具体测量结果，在此处复制，因此上面的目标背后有一些具体的东西。每一个都是在同一场景中进行同类比较。

| 测量 | Vite | UE5 | 比率 |
|---|---|---|---|
| DDGI测试场景，RTX 4080S，1440p原生 | 811 FPS (RTXGI) | 324 FPS (Lumen 5.7) | ~2.5x |
| DDGI 测试场景，RX 6600，1080p 原生 | 245 FPS (RTXGI) | &mdash; | &mdash; |
| 物理压力场景，3,000 个立方体 | 157 FPS (PhysX) | 33.3 FPS (Chaos 5.7.3) | ~4.7x |
| 物理求解器，10,005 个刚体，6 线程 | 11.76 ms (Vite PhysX) | 791.97 ms (Chaos) | ~67x |
| 物理，原生 PhysX actor 路径，1,425 个立方体 | 374 FPS | &mdash; | 非同口径比较；在 UE Vite 5.0 构建上测得 |
| 角色移动和碰撞 | 4.27 基线 | 5.6 | 4.27 上速度提高了 2.2–2.8 倍 |
| 典型的多人游戏地图内存 | ~1 GB 小于 5.7 | &mdash; | &mdash; |

DDGI 对比最能代表渲染方面的论据，物理对比最能代表 CPU 方面的论据。基准场景本身可以从[项目和演示](../ProjectsAndDemos.md)下载。

## 为什么原生分辨率是制约因素

时间重建、去噪与随机采样会引入噪声、残影、时间不稳定和模糊。即使帧率数字相同，动态 720p–1080p 内部分辨率重建到 4K 的 60 FPS 目标，与原生 4K 的 60 FPS 目标也是不同的产品。

Vite 的立场是，图像清晰度与操作响应性是最先劣化、也最难恢复的东西，因此帧时间预算应当花在保持原生分辨率、并使用构造上无噪声的光照技术上。 DDGI 用球谐函数在探针体积中存储并过滤辐照度，这正是它无需降噪器也能得到稳定结果的原因。

超分器得到完整支持——DLSS 4.5、FSR 4（带 FSR 3.1 回退）、XeSS 3 和 NIS 均随引擎一同提供。它们的定位是在较弱硬件上超越目标的手段，而不是在参考硬件上达到目标的手段。参见[超分辨率与帧生成](../Rendering/Upscalers.md)。

## 按目标设计

在制作内容之前确定目标，因为它决定了你全部的美术预算。

### 选择并保持性能目标

1. 从上表中选择与你的游戏类型相匹配的行。竞技多人游戏几乎总是意味着选择“风格化 4K120”目标；叙事型单人游戏通常能负担得起「保真」目标。

2. 只配置对应的功能集，不要多配。DDGI 默认开启，而各个光线追踪效果需要单独开启，因此大多数目标只意味着开启你那一行里的效果。参见[光线追踪](../Rendering/Ray-Tracing.md)。

3. 为每个系统（全局光照、反射、阴影、几何体、后期处理）设定帧时间预算，并从第一个可玩场景开始使用 `stat gpu` 命令进行测试。

4. 定期在你测试矩阵中最低的硬件上测试，而不是等到最后。请参阅[系统要求](../GettingStarted/System-Requirements.md)以获取参考硬件列表。

5. 使用[可扩展性](../Performance/Engine-Defaults.md)设置来降低配置，而不是先针对配置最低的机器进行设计，然后再进行扩展。
